Rate Limiting: 50 req/h per user (push), 100 max ops per batch

================================================================================
FIRST-WRITE-WINS ALGORITHM (DETERMINISTIC CONFLICT RESOLUTION)
================================================================================

When device tries to push update:

  clientTime < serverTime
  ├─ Client is stale → REJECT ❌
  └─ Notify user "Overwritten by [user]"

  clientTime > serverTime
  ├─ Client is newer → ACCEPT ✅
  └─ Update proceeds

  clientTime === serverTime (rare)
  ├─ UUID tiebreaker (deterministic)
  └─ Highest UUID wins

Result: NO complex merge UI, just notification

CRITICAL SUCCESS FACTORS
================================================================================

1. FWW algorithm must be deterministic (UUID tiebreaker implemented)
2. Transaction safety: every multi-entity sync in QueryRunner (R005)
3. tenantId validation: every operation validates JWT claim (R020)

5. Conflict UX: simple dialog, not complex merge tool
6. Performance: <500ms pull 1000 records, <1s push 100 ops

QUESTIONS ADDRESSED IN SPEC
================================================================================

Q: Why First-Write-Wins and not 3-way merge?
A: FWW is deterministic, no UI dialogs, simpler. Invoicing has mostly serial edits.

Q: What if token expires while offline?
A: Postpone sync. Auto-refresh on network return. User notified.

Q: Do we sync StockEntry?
A: No, too large (millions of FIFO records). Only sync FinishedProduct summaries.

Q: Can we use PowerSync?
A: Yes but it's paid. WatermelonDB is open-source, sufficient for MVP.

(See MOBILE_OFFLINE_README.md for complete Q&A)

RISK MITIGATION
================================================================================

Risk                              Mitigation
────────────────────────────────────────────────────────────────────────────
Large batch push (>1000 ops)      Rate limit: 50 req/h, max 100 ops/batch
Token expiry offline              SecureStore + auto-refresh on network
Conflict explosion                FWW is deterministic, no user dialogs
Data consistency                  Transaction wrapping (R005), soft delete
Performance on 1M records         Pagination, indexes, delta-sync
Cross-device sync                 Pull deltas sequential (eventual consistency)
